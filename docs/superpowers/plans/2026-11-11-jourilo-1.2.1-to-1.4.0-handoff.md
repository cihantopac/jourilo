## Lessons from 1.2.0 (apply them)

- **A unit test must mirror the field evidence, not an idealised case.** F5 passed its unit test but failed on
  cihanca.com, because the real keyboard-walk evidence had a class-less selector and a text-only snippet. Before
  closing a detection task, compare the test input with the real `run.json` evidence in the report.
- **Run the real-project check before the final review, not after.** It found the only release-blocking defect.
- **Worktrees under `.claude/worktrees/` break `npm run ci`.** Biome finds the nested `biome.json`. Remove an agent
  worktree (and its branch, with `git worktree remove` then `git branch -D`) once its commit is cherry-picked.
- `.superpowers/` is excluded from biome in `biome.json`.
- **Rebuilding `plugin/dist` while the ACT benchmark runs changes what it measures.** Run ACT last, on the final code,
  and label the result with the commit.
- **Windows CI:**
  - there are no POSIX signals, so signal tests use `it.skipIf(process.platform === 'win32')`;
  - lab performance findings vary on slow runners, so behaviour comparisons filter `perf/`;
  - `--max-duration` is the portable way to stop.
- **Commit trailer:** `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. One 1.2.0 subagent wrote "Sonnet";
  check every commit before pushing.
