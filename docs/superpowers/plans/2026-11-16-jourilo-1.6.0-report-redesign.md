# Jourilo 1.6.0 Plan: report redesign and README refresh

> **For agentic workers:** run with the lighter process: one implementer per task, controller reads the diff and
> screenshots, no reviewer agents. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A calm, visual, ordered HTML report on a strict 60/30/10 paper/ink/brass palette with folded details, and a
README rebuilt around new screenshots of it.

**Architecture:** Same string renderer (`src/report/html.ts`) and data. A new token set and component CSS in
`html-style.ts`, a new finding/card anatomy in `html.ts`, shorter EN/TR copy in `html-i18n.ts`; client behaviour in
`html-client.ts` keeps working against the new markup.

**Tech stack:** TypeScript, inline CSS/SVG, Playwright for screenshots, vitest.

**Spec:** [2026-11-16-report-redesign-design.md](../specs/2026-11-16-report-redesign-design.md)

## Global constraints

- **Palette, 60/30/10:**
  - 60 % paper (`--paper`, `--sheet`), 30 % ink (`--ink` and its tints), 10 % brass (`--brass`), used only for
    buttons, links, hover, the selected tab, focus and the checkbox accent.
  - Dark theme: the same roles.
- **Colour outside the palette:**
  - Severity colour appears only as an 8 px dot before the severity word.
  - Good/poor colour appears only in metric values (the pages table, trends, compare counts), never as a fill or
    border.
- **Copy:**
  - Every visible label is as short as possible, ≤ 3 words where it can be.
  - Detail is folded (`<details>`), not removed.
  - EN and TR are both updated.
- **Report:**
  - The report stays one offline file under its CSP: no external fonts or scripts.
  - Text contrast ≥ 4.5:1 in both themes.
  - Keyboard and screen-reader use is unchanged or better.
- **Constants:**
  - `RUN_SCHEMA_VERSION` stays 1.
  - `dependencies` stay `playwright-core` only.
  - No overall score; never imply WCAG conformance.
- **Commits:** the trailer is `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never commit `branding/`.
  `plugin/dist` is rebuilt and committed; revert line-ending-only license changes.
- **Tests:** focused per task; full `npm run ci` and `npm run bench` once, in Task 4.

## Review focus

- **A finding with no screenshot evidence** (e.g. a missing `lang`): the open state shows the fix and the details
  without an empty image frame.
- **A finding with no numeric `evidence.data`:** no stat tiles and no empty row.
- **The Turkish UI with long Turkish words:** chips and titles wrap without horizontal scrolling at 360 px.
- **Dark theme:** dots, the brass accent and code excerpts all stay readable.
- **The compare report and `report --format html` on an older run:** they render with the new styles (no unstyled
  markup).

### Task 1: Visual system and finding anatomy

**Files:** `src/report/html-style.ts`, `src/report/html.ts` (`chipsHtml`, `groupHtml`, `cardHtml`,
`evidenceHtml`), `src/report/html-i18n.ts`, `src/report/html-client.ts` (only if selectors change),
`tests/unit/report-ui.test.ts`, `tests/unit/report.test.ts`.

- [x] **Tokens:**
  - Redefine LIGHT/DARK around paper/ink/brass.
  - Drop the `--*-soft` severity fills.
  - Add one `--dot-{critical,serious,moderate,minor}` set.
  - Build hierarchy from type scale and spacing: one scale, fewer borders, 12–16 px radii, softer shadow.
- [x] **Severity:** a new `sevHtml(sev): string` renders `<span class="sev"><i class="dot dot-<sev>"
  aria-hidden="true"></i>Serious</span>`. Every place that today draws a severity chip, border or tint uses it instead.
- [x] **Chips:** fix-path, category, status and occurrence chips all share one neutral style. `rc.samecause` and the
  "×N" chip become one short muted meta line ("2 pages · ×10").
- [x] **Finding (`groupHtml`):**
  - The summary row shows the dot plus severity word, the title, `where` and the checkbox.
  - Opening it shows, in this order:
    - the evidence visual, large (the first crop or screenshot);
    - stat tiles from the first evidence item's numeric `data` (at most 3, label plus value, e.g. "width 640");
    - one "Fix" sentence (`recommendation`).
  - Then a `<details class="more">` labelled "Details" holds: description, why, basis and confidence, standards,
    reproduction, rule and id, likely sources with excerpts, same-cause instances, affected pages and the full
    evidence list.
  - New helper: `statsHtml(f: Finding): string`, returning `''` when there are no numeric values.
- [x] **Overview card (`cardHtml`):**
  - Visual on top.
  - Dot plus severity word, then the title.
  - One meta line (where · source file) and the checkbox.
  - No chip row.
- [x] **i18n:** shorten EN/TR labels touched here ("Why it matters" → "Why", "Suggested fix" → "Fix",
  "Select for the repair prompt" → "Select", "same cause on N pages" → "N pages") and add `fd.details`.
- [x] **Tests:** in `report-ui.test.ts`:
  - `severity is a dot plus word`: no `sev-critical` background class remains, and `.dot-critical` exists.
  - `details are folded`: standards and reproduction sit inside `details.more`.
  - `no empty stat row when evidence has no numbers`.
  - `no empty visual when a finding has no screenshot`.

  Update the existing assertions that pin the old markup.
- [x] **Run:** `npx vitest run tests/unit/report-ui.test.ts tests/unit/report.test.ts tests/unit/rule-text.test.ts`.
  Then build and render the acme report, and screenshot overview and findings in light/dark at 1280 px and 390 px with
  `scripts/screenshot.mjs`.
- [x] **Commit:** `feat(report): calm 60/30/10 visual system, severity dots, folded finding details`.
