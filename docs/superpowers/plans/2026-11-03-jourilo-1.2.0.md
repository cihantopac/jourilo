# Jourilo 1.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the detection, location and journey defects found on real projects, let people set the page state
before an audit, let a false positive be dismissed, and make runs dependable for automation.

**Architecture:** Every change is a narrow edit to an existing module: in-page scripts in `src/browser/`, the
locator in `src/repair/locate.ts`, the journey runner and suggester in `src/journeys/`, orchestration in
`src/audit/engine.ts` and the CLI in `src/cli/commands/`. New behaviour is opt-in through flags. `run.json` only gains
optional fields, so `schemaVersion` stays 1.

**Tech Stack:** TypeScript 7, Node ≥ 20.10, playwright-core 1.64.1, axe-core 4.14.0 (bundled), vitest 5, biome 2.6.

**Spec:** [docs/FIELD-FEEDBACK.md](../../FIELD-FEEDBACK.md), items F1–F18 (with cihanca.com evidence in
`cihantopac/cihanca.com@next:docs/verification/jourilo/summary.md`).

## Global Constraints

- Source code, comments, tests and public docs are in English. Messages to Cihan are in Turkish.
- No overall UX score (DECISIONS D3).
- No new runtime dependencies. `playwright-core` stays at 1.64.1.
- `RUN_SCHEMA_VERSION` stays 1. New `Run` and `Finding` fields are optional, and old runs still load.
- Every detection change ships with a fixture page that must fire and a control page that must not. `npm run bench`
  keeps every existing `mustFind` with 0 false positives.
- Never imply WCAG conformance. The engine changes, so the ACT benchmark is rerun (Task 15) and reported as
  measured.
- Audits stay read-only. A setup journey runs under the same safety policy as `journeys run` and never pays,
  deletes or cancels on non-local hosts.
- The offline report never claims to execute anything.
- Exit codes: 0 ok, 1 failed gate or error, 2 usage, 3 refused for safety, 4 browser unavailable. New: **5 no page
  could be loaded**, **6 stopped early (partial run)**.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work on branch `release/1.2.0`
  and never push without Cihan's go-ahead.

## Review Focus

1. **A visually hidden input under its styled label, or a transparent click-catcher over a link.** Neither may be
   reported as focus obscured (Task 1 control page).
2. **A dismissed finding in `verify`.** It must show as dismissed, not as "fixed". A finding whose fingerprint
   changed (for example, a new URL) comes back as new rather than staying silently hidden (Task 7).
3. **A stop signal before the first page loads** (during browser launch or crawl). The run must still write a partial
   `run.json` with 0 pages and exit 6 without hanging. A second signal exits at once (Task 9).
4. **An invalid `--clock` date or `--timezone` id.** Exit 2 with a clear message before the browser starts (Task 5).
5. **`--evidence minimal` when a finding points at a full-page screenshot.** That file is kept, and the report
   renders when a page screenshot is absent (Task 12).

The schema covers:

- `Run`, `Finding`, `Evidence`, `PageCapture`, `JourneyResult` and `Manifest`;
- the required keys exactly as in `src/core/types.ts`;
- no `additionalProperties: false` anywhere, because readers must ignore unknown fields.

`docs/RUN-FORMAT.md` states the policy:

- within `schemaVersion` 1, fields are only added and are optional;
- removing, renaming or changing a field's meaning increments `schemaVersion`;
