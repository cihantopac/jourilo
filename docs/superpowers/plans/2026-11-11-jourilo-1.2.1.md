# Jourilo 1.2.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the false positives that 1.2.0 shows on real modern front ends, make the automation contract of
1.2.0 hold at its edges, and close the URL and loopback gaps measured by Frameva.

**Architecture:** Narrow edits to existing modules. These are the in-page probes (`src/browser/keyboard.ts`,
`src/browser/widgets.ts`, `src/browser/inpage/probe.js`), the rule builders (`src/audit/rules/*.ts`), URL safety and
crawl (`src/core/url-safety.ts`, `src/discovery/crawl.ts`), and the audit CLI and engine. No new module except where a
task says so. The new `run.json` field is optional, so `schemaVersion` stays 1.

**Tech Stack:** TypeScript, Node ≥ 20.10, playwright-core 1.64.1, axe-core 4.14.0 (bundled), vitest, biome.

**Spec:** [docs/FIELD-FEEDBACK.md](../../FIELD-FEEDBACK.md), items F20, F24, F25, F27, F28, F30, F32–F34, F37, F39 and
F40. F19 is decided by Cihan on 2026-11-11 as an opt-in deny. The 1.2.0 follow-ups come from
[docs/ROADMAP.md](../../ROADMAP.md) ("1.2.x follow-ups"). Evidence for every item is in
`/Users/cihan/Developer/frameva/docs/tool-feedback/jourilo/`.

- Source code, comments, tests and public docs are in English. Messages to Cihan are in Turkish.

  `additionalProperties: false`.

  fire. `npm run bench` keeps every existing `mustFind`, with 0 false positives and source location 10 / 10. Baseline:
  47 / 47.
- Audits stay read-only. The network guard keeps classifying every destination.
- Exit codes are unchanged:
  - 0 ok;
  - 1 failed gate or error;
  - 2 usage;
  - 3 refused for safety;
  - 4 browser unavailable;
  - 5 no page could be loaded;
  - 6 stopped early.
- Fingerprints of existing findings stay stable, unless a task says otherwise.
- Every new flag is documented in its command's `details`. `tests/unit/cli-docs.test.ts` enforces this.
- Branch `release/1.2.1`. Commit per task, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  Never push without Cihan's go-ahead.

## Review Focus

1. **A skip link that is off-screen until focused.** It has a box while focused and must still be checked. Task 1
   measures the area of the focused element, not the unfocused one.
2. **A dialog whose focus really escapes.** It must still be reported after the stability wait. Task 2 keeps the
   widgets-lab `/broken` control.
3. **Two crawl links that differ only by a trailing slash (`/a` and `/a/`).** The page is audited once. The explicitly
   requested form wins. Task 8 tests this.
4. **`--deny-local` with a public target that redirects to `localhost`.** The redirect is blocked by the guard and
   never audited. Task 9 tests this.
5. **`--max-duration` while a form probe or a slow page is in progress.** The run ends within the limit plus 5 s with
   exit 6, and no browser is left running. Task 10 tests this.

### Task 2: Dialog focus containment waits for focus guards (F30)

**Files:**

- Modify: `src/browser/widgets.ts` (the Tab loop after `issue('dialog-focus-escapes', …)`, around line 295)
- Create: `fixtures/sites/widgets-lab/dialog-guards.html`
- Modify: `fixtures/sites/widgets-lab/expected.json` and `index.html`

Steps:

- [ ] **Fixture.** `dialog-guards.html` implements the guard pattern of Base UI, Radix and React Aria:
  - a `role="dialog" aria-modal="true"` with two buttons;
  - a `<span tabindex="0" aria-hidden="true" data-base-ui-focus-guard>` before and after the buttons.

  Focusing a guard moves focus to the first (or last) button in `setTimeout(…, 30)`. Escape closes the dialog, and
  focus returns to the trigger. In `expected.json`, `mustNotFind` lists `jourilo/dialog-focus-containment` on
  `/dialog-guards`. The existing `/broken` page keeps its containment `mustFind` (Review Focus 2).
- [ ] Run the widgets-lab bench. Expected: FAIL, with a false positive on `/dialog-guards`.
- [ ] **Implement.**
  - After the Tab presses, wait until `document.activeElement` (deep, through shadow roots) is the same for two
    consecutive animation frames, at most 250 ms. Only then read `state()`.
  - A stop counts as an escape only when it is not a sentinel. A sentinel has no text, and has `aria-hidden="true"` or
    an attribute whose name matches `/focus-?guard|focus-?trap|data-.*sentinel/i`.
  - If focus sits on a sentinel after the wait, the dialog passes.
- [ ] Run `npm run build && npm run bench`. Expected: widgets-lab passes, `/broken` items are still found, and there
  are 0 false positives.
- [ ] Commit: `fix(widgets): wait for dialog focus guards before judging containment`.
