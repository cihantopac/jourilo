# Jourilo 1.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every remaining field-feedback item. That means decided contrast over images, runs that work behind
corporate proxies and with custom headers, an opt-in Chromium sandbox, honest page counts, redirect-chain and
keyboard-trap detection, a rule registry, budgets, `--wait-for`, structured progress, stable evidence and
origin-independent artifact names.

**Architecture:** One task per item, each in the module that already owns the behaviour. Everything new in `run.json`
or `manifest.json` is an optional field, so both stay at schema version 1 under docs/RUN-FORMAT.md. New flags are
opt-in. Defaults change only where the field report shows the default is wrong (F38 file names).

**Tech Stack:** TypeScript, Node ≥ 20.10, playwright-core 1.64.1, axe-core 4.14.0 (bundled), vitest, biome.

**Spec:** [docs/FIELD-FEEDBACK.md](../../FIELD-FEEDBACK.md), items F8, F15, F16, F21, F22, F23, F26, F29, F31, F35,
F36 and F38. It builds on 1.2.1 ([plan](2026-11-11-jourilo-1.2.1.md)), which must be released first.

## Decisions

- **F21** (Cihan, 2026-11-11): the Chromium sandbox is opt-in.
- **F22:** `summary.pages` keeps its meaning, which is captures. It cannot change within schema version 1. New fields
  carry distinct URLs and the truncation.
- **F36:** CLS from font swaps is real layout shift and stays in the metric. The fix makes evidence keys stable and
  documents the variance.
- **F16:** `--output-dir` is not added. The existing `--workspace` covers it, and the docs say so.
- **Extra headers** go only to the target's origin, never to third parties, so a credential header cannot leak.

## Global Constraints

- Source code, comments, tests and public docs are in English. Messages to Cihan are in Turkish.
- No overall UX score (DECISIONS D3). Never imply WCAG conformance.
- No new runtime dependencies. `playwright-core` stays at 1.64.1.
- `RUN_SCHEMA_VERSION` stays 1. Every new field is optional and is added to `schemas/run.schema.json`, without
  `additionalProperties: false`.
- Every detection change ships with a fixture that must fire and a control that must not. `npm run bench` keeps every
  existing `mustFind`, with 0 false positives. The ACT benchmark is rerun (Task 13), and its false positives must not
  exceed 1.2.1's.
- The network guard checks every final destination. No option bypasses it, including the upstream proxy and
  `--ignore-https-errors`.
- Every new flag is in its command's `details`. Secrets (proxy credentials, header values) are never written to
  `run.json`, reports, progress lines or the manifest.
- Exit codes: 0 ok, 1 failed gate or error, 2 usage, 3 refused for safety, 4 browser unavailable, 5 no page loaded,
  6 stopped early. A failed budget is exit 1.
- Branch `release/1.3.0`. Commit per task with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. No push
  without Cihan's go-ahead.

## Review Focus

1. **Text over a busy photo where some pixels pass and some fail.** The decision uses the worst case, so it is not
   decided as a pass. Task 1 tests this.
2. **An upstream proxy that resolves names itself.** The guard sends `CONNECT <checked IP>:<port>`, never the host
   name, so DNS rebinding through the proxy is impossible. Task 2 tests this.
3. **`--extra-header "Authorization: …"` on a page that loads third-party scripts.** The header reaches only the
   target origin. Task 3 tests this.
4. **A budget on a metric that was not measured** (INP without interaction). This is reported as "not measured", not
   as a pass or a fail. Task 8 tests this.
5. **`--wait-for` with a selector that never appears.** The page is still audited after `--timeout`, with a limitation.
   It is not counted as unreachable. Task 9 tests this.

### Task 1: Decide contrast over images by sampling pixels (F8)

**Files:**

- Create: `src/browser/contrast-sample.ts`
- Modify: `src/browser/capture.ts` (`runAxe`, around line 257). After axe, sample the `incomplete`
  `color-contrast` nodes whose reason is a background image, gradient or overlap, at most 30 nodes per capture.
- Modify: `src/audit/rules/accessibility.ts`, the axe-review block around line 109.
- Create: `fixtures/sites/structure-lab/contrast-image.html` (or a new `contrast-lab`) plus `expected.json`

**Interfaces:**

- Produces `export async function sampleContrast(page: Page, target: string): Promise<{ worst: number; best: number;
  large: boolean } | null>`.
  - It takes a clipped PNG screenshot of the node's rect and decodes it in the page, with a canvas over the PNG data
    URL, so no dependency is needed.
  - Text pixels are those nearest the computed `color`.
  - Background pixels are the 20 % of pixels farthest from it.
  - It returns WCAG contrast ratios: the text colour against the lightest and darkest background pixel.

Steps:

- [ ] **Fixture.**
  - Fails: white text over a light photo, worst-case contrast below 3:1.
  - Passes: white text over a dark photo, worst case ≥ 7:1.
  - Mixed: white text over a half-light, half-dark photo (Review Focus 1).
  - In `expected.json`: `mustFind` `jourilo/contrast-over-image` on the first and the mixed page. `mustNotFind` both
    `jourilo/contrast-over-image` and `axe-review/color-contrast` on the dark page.
- [ ] Run that lab's bench. Expected: FAIL.
- [ ] **Implement.**
  - The threshold is 4.5:1, or 3:1 when `large` (≥ 24 px, or ≥ 18.66 px bold).
  - `worst < threshold` gives the finding `jourilo/contrast-over-image`: serious, `defect`, provenance `measured`,
    confidence `medium`, WCAG 1.4.3, and evidence with the sampled worst ratio.
  - `best ≥ threshold && worst ≥ threshold` drops the review node.
  - Anything else stays `axe-review/color-contrast`.
  - Add `jourilo/contrast-over-image` to `VISUAL_STATE_RULES` in `src/repair/locate.ts`.
- [ ] Run `npm run build && npm run bench`. Expected: pass, with 0 false positives.
- [ ] Commit: `feat(contrast): decide contrast over images by sampling rendered pixels`.
