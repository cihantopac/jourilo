# Jourilo 1.4.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the whole "Next (1.x)" roadmap:
- full menu keyboard patterns;
- AST-based route and component discovery with component-level root causes;
- two new deterministic fixers;
- normalized trends;
- read-only PostHog, GrowthBook and Amplitude adapters with sequential testing;
- multi-tab and OAuth-popup journeys;
- Italian, Portuguese and Dutch vocabulary;
- Turkish rule texts in the report.

**Architecture:** Each roadmap item is a vertical slice in the module that owns it:
- `src/browser/widgets.ts` for menus;
- a new `src/discovery/ast/` for parsing;
- `src/repair/fixes.ts` for fixers;
- `src/report/` for trends and translations;
- a new `src/experiment/adapters/` for analytics;
- `src/journeys/runner.ts` for tabs;
- `src/core/lexicon.ts` for languages.

The TypeScript compiler is bundled into a separately loaded chunk, so the CLI only loads it when discovery parses
code.

**Tech Stack:** TypeScript, Node ≥ 20.10, playwright-core 1.64.1, axe-core 4.14.0 and typescript (both bundled, not
runtime dependencies), vitest, biome.

**Spec:** [docs/ROADMAP.md](../../ROADMAP.md) "Next (1.x)", items 1–8. It builds on 1.3.0
([plan](2026-11-11-jourilo-1.3.0.md)), whose rule registry (`src/audit/rules/registry.ts`) Task 10 uses.

## Decisions (Cihan, 2026-11-11)

- **AST parsing:** bundle the TypeScript compiler (as with axe-core). Vue and Svelte `<script>` blocks are extracted
  and parsed by the same parser. The package grows from about 2.3 MB to about 12 MB. That is accepted.
- **Analytics adapters:** PostHog, GrowthBook and Amplitude, all read-only. API keys come from environment variables
  and are never written anywhere. Tests use recorded responses.
- **New languages:** Italian, Portuguese and Dutch. Each has a fixture site.

## Global Constraints

- Source code, comments, tests and public docs are in English. Messages to Cihan are in Turkish.
- No overall UX score (DECISIONS D3). Never imply WCAG conformance.
- **Dependencies:**
  - `dependencies` stays `playwright-core` 1.64.1 only;
  - `typescript` moves from a pinned dev dependency into the bundle, in a separate chunk `plugin/dist/ts-parser.mjs`
    loaded with `import()`;
  - adapters use Node's `fetch`, with no SDKs.
- `RUN_SCHEMA_VERSION` stays 1 (optional fields only, added to `schemas/run.schema.json`). The journey schema gains
  optional step actions only, so existing journeys stay valid.
- Every detection change ships with a fixture that must fire and a control that must not. `npm run bench` keeps every
  existing `mustFind`, with 0 false positives. The ACT benchmark is rerun.
- Analytics adapters are read-only:
  - only `GET` requests, or the vendors' documented read-only query `POST` endpoints;
  - only through the guarded fetch;
  - keys never appear in runs, reports, progress lines, manifests or error messages.
- Journeys keep the safety policy for every tab and popup. OAuth popups are allowed only to local hosts or to origins
  the journey lists in `allowOrigins`, so only test identity providers are reachable.
- Every new flag and command is in the CLI `details`.
- Branch `release/1.4.0`. Commit per task with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. No push
  without Cihan's go-ahead.

## Review Focus

1. **A menu whose items are links that navigate.** Arrow-key checks must not activate an item, so no Enter or Space,
   and must restore the page afterwards. Task 1 tests this.
2. **A TS file with syntax the bundled TypeScript cannot parse (new syntax, or a broken file).** Discovery falls back
   to the regex routes for that file and says so. It must never fail the run. Task 2 tests this.
3. **An adapter response that is paginated, rate-limited (429) or has a missing variant.** It is reported as
   incomplete data, and the analysis does not run on partial numbers. Task 6 tests this.
4. **A popup that opens a third-party login page not listed in `allowOrigins`.** It is blocked, and the journey
   reports "blocked by policy". Task 8 tests this.
5. **A Turkish report for a rule without a translation.** It shows the English text with `lang="en"`. It is never
   empty. Task 10 tests this, and the parity test makes it unreachable for native rules.

### Task 7: Sequential testing (Next 5, part 2)

**Files:**

- Modify: `src/experiment/stats.ts`. Add `export function sequentialTest(a: { n: number; x: number }, b: { n: number;
  x: number }, opts: { alpha: number; tau?: number }): { pValue: number; decision: 'continue' | 'stop-b-better' |
  'stop-a-better'; confidenceInterval: [number, number] }`.
  - It uses the mixture sequential probability ratio test (mSPRT), with a normal mixing distribution with variance
    `tau²` (default `tau` is 0.1 on the difference in proportions) and always-valid p-values.
  - The source is cited in `docs/research/standards.md` §4.
- Modify: `src/cli/commands/experiment.ts`. `analyze --sequential`. It is the default with `--from`, since a live
  experiment is checked repeatedly.
- Test: `tests/unit/stats.test.ts`

Steps:

- [ ] **Test** `with no difference, 1000 simulated peeks keep the false stop rate under alpha`. Use a seeded
  generator in the test only.
- [ ] **Test** `a large true difference stops for the better variant`.
- [ ] **Test** `the p-value never increases as data accumulates`. This is the always-valid property.
- [ ] Run the tests. Expected: FAIL.
- [ ] Implement, then run the tests. Expected: PASS.
- [ ] Commit: `feat(experiment): mSPRT sequential testing with always-valid p-values`.
