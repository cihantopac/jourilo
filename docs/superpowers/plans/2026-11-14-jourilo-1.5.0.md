# Jourilo 1.5.0 Plan: close every deferred item

**Goal:** Close every open item left after 1.4.0 (the 1.3.0 and 1.4.0 deferred minors and F43), in one release.

**Source:** [handoff after 1.4.0](2026-11-14-jourilo-1.5.0-handoff.md), "Candidates for 1.5.0". Each task below names
the items it closes; together they cover the whole list.

## How this release runs (Cihan, 2026-11-14: fast, clean, few tokens)

- **One branch** `release/1.5.0`, **one PR**, **one tag**. No per-task branches, worktrees or PRs.
- **One commit per task** (a fix commit on top only if the controller sends one back).
- Per task: one implementer agent (Sonnet) gets the task text below as its brief, runs focused tests only, commits and
  writes a short report (status, commit, tests run, anything it could not do). No reviewer agents. The controller reads
  the diff, accepts it or sends one short fix to the same agent.
- No ledger files or review packages: progress is the checkboxes in this file, updated by the controller.
- A sub-item that turns out to need a design decision or more than a small change is not forced: the implementer leaves
  it, says why in the report, and the controller lists it under "Not done" in the release notes.
- Full `npm run ci` and `npm run bench` run once, in Task 9, before push. One heavy run at a time (16 GB Mac).

## Global constraints

- Code, comments, tests and docs in English; messages to Cihan in Turkish.
- `RUN_SCHEMA_VERSION` stays 1; new fields optional. `dependencies` stays `playwright-core` only.
- A detection change ships with a fixture or unit case that must fire and a control that must not; `npm run bench`
  keeps every `mustFind` with 0 false positives.
- No overall UX score, never imply WCAG conformance (D3).
- Behaviour changes get one CHANGELOG line (written in Task 9 from the reports) and, where a limitation goes away or
  changes, the matching line in `docs/LIMITATIONS.md` in the same task.
- Commit trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never commit `branding/`.
